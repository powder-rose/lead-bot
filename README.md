# LeadBot

Инструмент для небольшой доверенной команды на закрытом сервере. Все пользователи входят по общему паролю и имеют одинаковый доступ к компаниям, импорту, сканеру и кампаниям.

## Локальный запуск

Нужен Node.js 22.22 или новее в ветке 22 LTS.

1. Установите зависимости: `npm ci`, `npm --prefix client ci`, `npm --prefix server ci`.
2. В каталоге `server` выполните `npx playwright install chromium`.
3. Скопируйте `server/.env.example` в `server/.env`. Задайте `LEADBOT_ACCESS_PASSWORD`: уникальный случайный пароль не короче 16 символов. Файлы `.env` исключены из Git. Не используйте переменные с префиксом `VITE_` для пароля.
4. Запустите `npm --prefix server run dev` и отдельно `npm --prefix client run dev`.
5. Откройте `http://localhost:5173` и войдите. Используйте именно этот адрес: `LEADBOT_ORIGIN` должен точно совпадать с адресом в браузере.

Клиент отправляет запросы на `/api` своего origin. Vite перенаправляет их на `127.0.0.1:3000`. Если меняете `PORT`, измените также адрес локального proxy в `client/vite.config.js`. По умолчанию оба сервера слушают только локальный интерфейс.

## Закрытый сервер

Перед обновлением сохраните резервную копию базы. При переходе со старой версии сначала задайте пароль и адрес сайта: без корректного пароля новая версия сервера не запускается.

- Установите `NODE_ENV=production` и `LEADBOT_ORIGIN=https://ваш-домен` без завершающего `/`.
- Задайте случайный `LEADBOT_ACCESS_PASSWORD` через окружение службы или `server/.env` с доступом только у владельца процесса.
- Соберите клиент: `npm --prefix client run build`.
- HTTPS reverse proxy должен отдавать `client/dist`, направлять `/api/` на `http://127.0.0.1:3000` и возвращать `index.html` для клиентских маршрутов. API не должен попадать под SPA fallback. Не кэшируйте ответы `/api/` и не удаляйте cookie или заголовок `X-LeadBot-Request`.
- Запустите `npm --prefix server start`. Порт backend держите закрытым от внешней сети. Для контейнера можно явно задать `HOST=0.0.0.0`; публикацию порта ограничьте сетью proxy.
- Проверьте `/api/health`, вход, обновление страницы, выход и отказ `401` при запросе `/api/companies` без сессии. Проверьте запуск кампании после входа.

Вход по HTTP разрешён только на localhost при разработке. В production требуется HTTPS; cookie имеет флаги `Secure`, `HttpOnly`, `SameSite=Strict` и префикс `__Host-`. Сторонние browser origin отклоняются; изменяющие запросы требуют заголовок `X-LeadBot-Request: 1`.

## Сессии и ограничения

- Сессия действует 8 часов, выход отзывает её на сервере. Пароль и токен сессии не сохраняются в localStorage.
- Сессии хранятся только в памяти одного процесса, максимум 100 одновременно. Перезапуск завершает все сессии. Для нескольких процессов или отдельных учётных записей потребуется другая схема хранения и входа.
- На вход разрешено 10 попыток за 15 минут с одного сетевого адреса, включая успешные. За reverse proxy этот лимит общий для команды. `X-Forwarded-For` намеренно не используется, чтобы клиент не мог обходить ограничение. При превышении сервер возвращает `429` и `Retry-After`.
- Смена пароля: обновите окружение/`.env`, перезапустите сервер и передайте новый пароль доверенным пользователям. Это отзывает все прежние сессии.
- Выход закрывает доступ в браузере, но не останавливает уже запущенные кампании. Внутренний сканер использует отдельный случайный ключ процесса только для локального `POST /api/scan`; он не даёт доступ к базе или импорту. `LEADBOT_INTERNAL_API_URL`, если задан, допускает только `http://127.0.0.1:PORT`; переадресации запрещены.
- Общий пароль не даёт индивидуальных ролей и журнала действий по пользователям. Этот этап закрывает анонимный доступ. Ограничение адресов сканирования (SSRF) и остальные пункты аудита остаются отдельными этапами.

## Проверки

`npm run quality:check` проверяет форматирование, lint, сборку клиента, серверные тесты и вход в реальном Chromium. Зависимости и Chromium должны быть установлены, как описано выше.

- `npm --prefix server test` — серверные тесты, включая защиту всех групп API, сессии, CSRF, лимит входа и внутренний сканер. Тесты доступа используют безопасные обработчики без обращения к рабочей базе.
- `npm --prefix client run build` и затем `npm --prefix server run test:ui` — проверка формы входа, сохранения сессии, выхода и истечения сессии в собранном интерфейсе. Используется временный локальный сервер, рабочая база не открывается.
